# PixelComparison 数据上报接入指南

本文面向 UE 采集模块、渲染农场和 CI。目标是把一次采集产生的批次元数据与检查点截图可靠上报到 PixelComparison，并按需发起自动对比。

默认开发后端地址是 `http://127.0.0.1:8020`。接口没有鉴权，只能在可信网络使用。

## 1. 上报流程

一次完整上报分为三类数据和一个可选动作：

```text
POST /api/batches
        │ 创建批次，取得最终 batch id
        ├─────────────────────────────────────┐
        ▼                                     ▼
POST /api/batches/{id}/map-build-data   POST /api/batches/{id}/screenshots
        │ 可选；每批一份，重复调用原子替换       │ 每张截图调用一次
        └──────────────────┬──────────────────┘
                           ▼
POST /api/batches/{id}/auto-compare
          可选；全部截图上传完成后调用一次
```

不要在截图尚未全部上传时触发自动对比，否则结果会缺少尚未到达的检查点。

## 2. 推荐数据包结构

```text
<批次目录>/
  manifest.json
  Screenshot/
    01_广场.png

```

## 3. 创建批次

```http
POST /api/batches
Content-Type: application/json
```

请求字段：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `id` | string | 否 | 批次 ID；省略时取现有纯数字 ID 最大值加一 |
| `scene_id` | string | 是 | UE Level/World 名；同场景才能比较 |
| `platform` | string | 是 | 平台；WindowsEditor 等会被归一化 |
| `p4_version` | int/null | 否 | P4 changelist，越大越新 |
| `creator` | string | 否 | 默认 `CI机器人` |
| `batch_url` | string/null | 否 | CI/流水线链接 |
| `resolution` | string/null | 否 | 例如 `1920x1080` |
| `capture_type` | string/null | 否 | 例如 `levelsequence` |
| `levelsequence_name` | string/null | 否 | LevelSequence 名称 |
| `levelsequence_path` | string/null | 否 | LevelSequence 资源路径 |
| `shading_quality` | int/null | 否 | 画质档位 0–5 |
| `captured_at` | ISO8601 string | 否 | 采集时间；解析失败时回退到入库时间 |
| `overwrite` | bool | 否 | 同号批次存在时是否删旧建新，默认 `false` |

画质约定：

| 值 | 显示名 |
|---:|---|
| 0 | 节能 |
| 1 | 流畅 |
| 2 | 均衡 |
| 3 | 精美 |
| 4 | 极致 |
| 5 | 电影 |

历史数据或缺省值按 4（极致）显示。

请求示例：

```bash
curl -X POST http://127.0.0.1:8020/api/batches \
  -H "Content-Type: application/json" \
  -d '{
    "id": "101",
    "scene_id": "Lv_Starfall",
    "platform": "WindowsEditor",
    "p4_version": 251200,
    "shading_quality": 5,
    "resolution": "1920x1080",
    "creator": "render-farm-ci"
  }'
```

成功返回 `201`，响应中的 `id` 是后续上传必须使用的最终批次 ID。

### 重复批次语义

- `overwrite=false`：返回 409。客户端可以把它解释为“批次已存在”，继续补传截图。
- `overwrite=true`：级联删除旧批次、截图、相关对比、对比项、基线关联和派生图片，再创建新批次。
- 相关对比正在计算时，覆盖返回 409，应稍后重试。

覆盖是破坏性操作，不应作为普通网络重试策略。

## 4. 上传截图

```http
POST /api/batches/{batch_id}/screenshots
Content-Type: multipart/form-data
```

字段：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `scene_name` | text | 是 | 检查点唯一配对键 |
| `file` | file | 是 | 截图文件，当前约定使用 PNG |
| `camera` | JSON string | 否 | 相机位置和旋转 |
| `frame_index` | int | 否 | 帧序 |

示例：

```bash
curl -X POST http://127.0.0.1:8020/api/batches/101/screenshots \
  -F "scene_name=01_废弃都市_广场_昼" \
  -F "frame_index=0" \
  -F 'camera={"location":{"x":1,"y":2,"z":3},"rotation":{"pitch":0,"yaw":90,"roll":0}}' \
  -F "file=@Screenshot/01_废弃都市_广场_昼.png;type=image/png"
```

成功返回 `201`。常见失败：

- 404：批次不存在。
- 400：`scene_name` 是空值、`.`、`..`，或包含路径分隔符。
- 409：同一批次已存在相同 `scene_name`。

服务端当前会把上传内容保存到 `.png` 路径，采集端应确保文件确实是可解码 PNG。当前接口尚未实施应用层文件大小和像素数上限；调用方应主动限制单图尺寸，总体限制应在反向代理或后续服务端校验中补齐。

### 检查点命名建议

建议只使用中文、英文字母、数字、下划线和短横线，例如：

```text
01_废弃都市_广场_昼
SeqVillage_Frame0001
```

同一检查点在所有版本中必须保持完全相同的名字，否则会被识别为新增和缺失，而不是同一张图的差异。

## 5. 上传烘培数据

电影档批次可以随附一份 `map-build-data/v2` JSON。先创建批次并取得最终 ID，然后把文件内容作为请求体直接提交：

```http
POST /api/batches/{batch_id}/map-build-data?format=map-build-data%2Fv2
Content-Type: application/json
```

```bash
curl -X POST 'http://127.0.0.1:8020/api/batches/101/map-build-data?format=map-build-data%2Fv2' \
  -H 'Content-Type: application/json' \
  --data-binary @Artifacts/MapBuildData/map_build_data.json
```

顶层结构：

```json
{
  "worldAggregate": {
    "residentBytes": "433771743",
    "allMipsBytes": "441029855",
    "cookEstimateBytes": "344752317",
    "textureCount": "105"
  },
  "registries": [
    {
      "path": "/Game/Maps/Example_BuiltData_Block0_0x01",
      "parentPath": "/Game/Maps/Example_BuiltData_Block0",
      "blockIndex": 0,
      "subBlockIndex": 1,
      "self": {
        "residentBytes": "2453667",
        "allMipsBytes": "2453667",
        "cookEstimateBytes": "1800000",
        "textureCount": "3",
        "breakdown": {
          "lightmapTextures": { "residentBytes": "1000000", "allMipsBytes": "1000000", "cookEstimateBytes": "800000" },
          "hueTextures": { "residentBytes": "200000", "allMipsBytes": "200000", "cookEstimateBytes": "100000" },
          "shadowmapTextures": { "residentBytes": "900000", "allMipsBytes": "900000", "cookEstimateBytes": "700000" },
          "meshMapBuildDataBytes": "3664",
          "precomputedLightVolumeBytes": "22060992",
          "precomputedReflectionVolumeBytes": "480",
          "volumetricLightmapBytes": "0",
          "lightBuildDataBytes": "16",
          "reflectionCaptureBytes": "1572840",
          "precomputedInstancedILCBytes": "12686",
          "precomputedInstancedPRBytes": "0",
          "lightmapResourceClusterBytes": "528"
        }
      },
      "subtreeAggregate": {
        "residentBytes": "2453667",
        "allMipsBytes": "2453667",
        "cookEstimateBytes": "1800000",
        "textureCount": "3"
      }
    }
  ]
}
```

当前 UE 产物把 64 位字节数编码为十进制字符串，后端也兼容 JSON 整数。所有数值必须非负且不超过 SQLite 64 位整数范围；`path` 在单批次内唯一，`blockIndex/subBlockIndex` 坐标不能重复，子分块必须带所属分块索引，单批最多 5000 个 Registry。违反约束返回 `422`，不会写入半份数据。

成功返回 `201`：

```json
{
  "batch_id": "101",
  "scene_id": "Lv_Starfall",
  "format": "map-build-data/v2",
  "registry_count": 70,
  "updated": false
}
```

接口是按批次幂等替换：第一次上报 `updated=false`；网络重试或重新解析同一批次时，完整快照和 Registry 索引在一个事务内替换并返回 `updated=true`，不会产生重复行。客户端可以安全重试同一份数据，但不应把不同场景的数据写到同一个批次 ID。删除或 `overwrite=true` 覆盖批次时，烘培数据一起级联删除。

后端同时保留完整 JSON 和常用指标索引。页面查询接口为：

```http
GET /api/map-build/meta
GET /api/map-build/scenes/{scene_id}/overview?batch_id=101
GET /api/map-build/scenes/{scene_id}/trend?block_index=3&metric_scope=self&days=30
GET /api/map-build/scenes/{scene_id}/trend?registry_path=%2FGame%2FMaps%2Fmain%2FCoralWP%2FCoral_WP_BuiltData_BlockRefl.Coral_WP_BuiltData_BlockRefl&days=30
```

`overview` 返回指定或最新批次的独立主分块/分块/子分块网格，不查询上一批次，也不返回增量；省略 `batch_id` 即取最新。`world.path`、`blocks[].path` 和 `sub_blocks[].path` 分别给出对应 Registry 路径，拓扑不完整时前两者可能为 `null`。每个节点的 `self_metrics` 表示节点自身，`subtree_metrics` 表示节点自身与全部后代的汇总，`has_children` 表示是否可切换口径；兼容字段 `metrics` 仍指向 `subtree_metrics`。概览除总 Mip 与 Cook 估算外，还会把上述 breakdown 资源项展开为稳定的 snake_case 指标；旧上报缺少可选资源项时按 0 处理。

`trend` 省略索引和路径时查主分块，只传 `block_index` 时查对应数字分块，同时传两个索引时查子分块。`BlockRefl` 等没有数字索引的直属节点使用概览响应中返回的完整 `path` 作为 `registry_path`；它不能与 `block_index` 或 `sub_block_index` 同时使用。`metric_scope=self` 是默认口径，`metric_scope=subtree` 返回含子级汇总；`days` 范围为 1～365，时间窗口以场景最新快照日期为结束日。一天内多个批次都会保留并按时间、批次 ID 排序；单次最多返回最新 2000 个点，超过时响应的 `window.truncated` 为 `true`。前端不按平台和画质筛选；接口仍兼容可选的 `platform` 与 `shading_quality` 参数，供外部程序需要限定产出条件时使用。

## 6. 自动选择参照批次

全部截图上传成功后调用：

```http
POST /api/batches/{batch_id}/auto-compare
```

选择范围是同 `scene_id`、同归一化平台、同画质的历史批次。

选择顺序：

1. 当前批次有 P4 版本时，优先选择更小且最接近的 P4 版本。
2. 没有更小版本时，在相同 P4 中选择创建时间更早且最近的批次。
3. 当前批次没有 P4 时，按创建时间选择更早且最近的批次。

找到参照：

```json
{
  "matched": true,
  "ref_batch_id": "100",
  "task_id": "...",
  "status": "running"
}
```

没有参照：

```json
{
  "matched": false
}
```

找到已有缓存时，响应也可能直接包含 `status: "done"` 和 `comparison`。

## 7. 手动发起对比

```http
POST /api/comparisons
Content-Type: application/json
```

```json
{
  "batch_id": "101",
  "ref_batch_id": "100",
  "force": false
}
```

规则：

- 两个 ID 不能相同。
- 两个批次必须有相同 `scene_id`，平台可不同。
- 同一无方向批次对只保存一条结果。
- 已有结果且 `force=false` 时直接返回缓存。
- `force=true` 强制重新计算。

新任务返回：

```json
{
  "task_id": "e3f...",
  "status": "running",
  "done": 0,
  "total": 0,
  "flip": false
}
```

轮询：

```http
GET /api/comparisons/tasks/{task_id}
```

运行中：

```json
{
  "status": "running",
  "done": 4,
  "total": 12
}
```

完成后响应包含 `comparison`。失败时状态为 `error`。

任务进度只保存在当前后端进程内存中。客户端应设置合理的总超时和网络重试，但不能把 404 的旧 task ID 当作成功；服务重启后需要重新查询或重新发起对比。

## 8. 查询已有对比

只检查缓存、不触发计算：

```http
GET /api/comparisons/lookup?batch_id=101&ref_batch_id=100
```

该接口忽略方向，返回已有 comparison 及按 `scene_name` 索引的热力图 URL。列表图使用它决定是显示热力图还是“发起对比”按钮。

对比列表：

```http
GET /api/comparisons
```

对比检查点：

```http
GET /api/comparisons/{comparison_id}/scenes?page=1&page_size=20&sort=diff&q=广场
```

单个检查点详情：

```http
GET /api/items/{item_id}
```

## 10. 浏览器手动上报

不需要编写客户端时，可以从前端顶栏打开手动上报：

1. 拖入数据包目录。
2. 检查解析后的批次信息、Registry 数量和缺失文件。
3. 必要时填写 P4 版本、选择是否覆盖和是否自动对比。
4. 开始上传并等待烘培数据和所有截图完成。

浏览器上报适合人工联调和少量补传；稳定 CI 应直接调用 API，并记录批次 ID、每张图片结果和最终 task ID。

## 12. 同步前端场景目录

外部模块可以下发一份权威场景目录，同时控制批次页“场景 ID”筛选框的内容和从上到下的顺序。接口采用全量替换语义，重复发送相同内容结果不变：

```http
PUT /api/scene-catalog
Content-Type: application/json
```

```json
{
  "scene_id_order": [
    "Village_Dimension_Main",
    "RottenVale_WP",
    "OtherScene"
  ]
}
```

请求示例：

```bash
curl -X PUT http://127.0.0.1:8020/api/scene-catalog \
  -H 'Content-Type: application/json' \
  -d '{"scene_id_order":["Village_Dimension_Main","RottenVale_WP","OtherScene"]}'
```

规则：

- 数组顺序就是筛选框顺序，每次请求完整覆盖上一次目录。
- 目录中的场景即使数据库中还没有任何批次，也会出现在筛选框；选择后显示空数据。
- 数据库中存在、但本次目录没有包含的场景不会删除数据，只会默认从筛选框隐藏。
- 项目设置开启“目录外场景”后，未列入目录但数据库中存在的场景按名称排序追加到末尾，并标记为“未配置”。
- 空数组是合法的，表示默认隐藏全部数据库场景；开启“目录外场景”后仍可查看它们。
- 场景 ID 必须非空、不能有首尾空格、不能重复，单项最长 255 个字符，列表最多 5000 项；违反约束返回 `422`，原目录保持不变。
- 当前打开的前端会在手动刷新、切回浏览器前台或最多一分钟的自动刷新后取得新目录。当前选中场景被隐藏时，筛选会自动清空。

读取当前权威目录：

```http
GET /api/scene-catalog
```

未曾同步时返回 `configured: false` 和 `scene_id_order: null`，前端保持兼容，按名称显示数据库中的全部场景。同步空数组后则返回 `configured: true` 和空列表，两种状态含义不同。

该接口会修改所有用户共享的项目级配置。当前项目没有身份认证，只应在可信内网中向受信任模块开放；多个模块同时写入时以最后一次成功请求为准。

## 13. 生产客户端建议

推荐实现以下行为：

1. 解析 manifest 前验证必填字段和截图文件是否存在。
2. 为创建批次、烘培快照、每张截图和自动对比记录结构化日志。
3. 连接失败和 5xx 使用有限次数的指数退避。
4. 409 按操作类型区分：批次存在可进入补传；截图存在可跳过；覆盖被阻止应稍后重试。
5. 对批次 ID 和 `scene_name` 做明确字符约束。
6. 设置请求超时和单图/总包大小限制。
7. manifest 声明烘培数据时校验文件存在，并按相同批次 ID 幂等重试。
8. 只有所有必需截图成功后才调用自动对比。
9. 若 CI 需要视觉质量门禁，轮询任务直到完成，并根据 pass/warn/fail 设计明确退出码。

## 14. 状态码速查

| 状态码 | 典型含义 |
|---:|---|
| 200 | 查询成功，或命中已有结果 |
| 201 | 批次/截图创建成功，或烘培快照写入/替换成功 |
| 202 | 对比任务已接受或自动对比请求已处理 |
| 204 | 客户端日志接收成功 |
| 400 | 参数非法、自比较、场景不一致 |
| 404 | 批次、任务、对比项或文件不存在 |
| 409 | 批次/截图重复，或计算中的对象不能删除/覆盖 |
| 422 | JSON、表单或参数类型不符合 FastAPI/Pydantic 模型 |
| 500 | 服务端异常；客户端可有限重试并保留请求上下文 |

## 15. 数据保留

- 原始批次和截图不会按时间自动删除，需要人工删除或使用维护脚本。
- 烘培快照保存在 SQLite 中并跟随批次生命周期，不受对比结果 14 天保留期影响。
- 对比结果默认保留 14 天，在后续对比创建或完成时淘汰。
- 截图上报成功后会异步预生成缩略图，不阻塞上传；缩略图是可重建缓存，默认按 60 天未访问淘汰。
- SQLite 数据库每天自动备份，默认保留 30 天。
- 数据库备份不包含截图文件；图片需要独立备份策略。

# SceneScope 热力图离线方案

## 工作区结构

查看器、共享配置和批次数据分开维护：

```text
SceneScopeOffline/
├─ SceneScopeOffline.exe         # 内嵌 Python 运行依赖和当前 Vue 前端
├─ config/
│  └─ heatmap.zip                # 唯一共享配置：地图、底图、标尺与绑定
└─ data/
   ├─ SceneScope-heatmap-main-67526.ssheat
   └─ SceneScope-heatmap-main-67527.ssheat
```

- 查看器长期复用，使用本机 HTTP 服务提供现有热力图读接口。
- `config/heatmap.zip` 固定一份，首次分发和配置变更时更新，不随每个批次重复生成。
- `data/*.ssheat` 每个包对应一次 GPMHeatmap 批次，可包含多张地图，只保存随批次变化的采集数据与缩略图。
- 新增数据包或替换共享配置后，刷新页面即可读取，不需要重新生成 EXE。

查看器按本地已有批次重建批次列表、上一批次变化和 7/14/30 天趋势。上一批次沿用在线的入库 ID 顺序；趋势按采集时间排列，以当前作用域最新采集时刻为窗口锚点。

这一步不包含 P4 发布。以后在流水线后增加独立发布适配器即可：日常提交新批次包，配置变更时单独更新共享配置。

## 共享配置

直接复用现有完整配置包 `pixelcomparison-gpm-config` v1（`scope=all`）：

```text
config/heatmap.zip
├─ manifest.json
├─ maps.json                    # 地图 ID、名称、坐标、轴向与底图引用
├─ metric-scales.json           # 每个指标标尺只保存一次
├─ scale-sets.json              # 指标 Key → 标尺 ID
├─ map-bindings.json            # 地图 × 平台 × 画质 → 标尺集 ID
└─ images/                      # 每张地图的底图只保存一次
```

所有批次统一使用当前这份配置。更新坐标、底图、标尺或绑定后，已有历史批次也按新配置显示；不保留各批次导出时的配置快照。平台和画质仍按绑定区分，配置与在线一样不按分支隔离。

指标未绑定标尺时，依据当前批次点位数据动态计算颜色范围。在线和离线共用标尺读模型，保持固定分段与动态着色规则一致。

有数据包时必须提供共享配置。缺失配置、不完整的配置包、无效引用、缺少数据包使用的地图或缺少已引用底图时，会明确报错。配置中合法的无底图地图仍可查看点位详情、缩略图和趋势。

底图 URL 带配置包内容摘要，替换配置后更新 URL，避免浏览器继续使用旧底图缓存。

## 批次数据包

`.ssheat` 本质是 ZIP，当前格式为 `scenescope.heatmap-pack` v2，要求查看器 v2：

```text
manifest.json
data/maps/<map>/frame.json
data/maps/<map>/points/<point_id>.json
assets/maps/<map>/thumbnails/<screenshot_id>.webp
```

| 内容 | 保存位置 |
|---|---|
| 批次号、分支、平台、画质、采集时间、P4 版本与来源链接 | `manifest.json` |
| 点位序号、位置、方向、指标数值、缩略图引用 | `frame.json` |
| 采集端上报的指标名称与顺序、方向显示开关、整体趋势汇总 | `frame.json` |
| 点位详细树状数据和单点趋势数据 | `points/<point_id>.json` |
| 截图 WebP 缩略图 | `assets/.../thumbnails/` |

包内不保存地图配置、底图、标尺表达式或解析后的着色规则，也不固化可用批次列表、上一批次和变化率等可重建数据。采集端上报的指标定义属于批次数据，不能因为当前内容相同就搬进共享配置。

截图的 `image_url` 与 `thumbnail_url` 指向同一张缩略图，截图条和放大查看继续可用，放大清晰度受缩略图尺寸限制。详情中的外部 HTTP 链接保留，断网时无法打开这些链接。

v1 自包含批次包不再被新查看器接受，需重新导出为 v2 并配套导出一次共享配置。查看器仍拒绝不支持的版本、不安全路径、重复批次和超出限制的压缩包。

## 导出和启动

首次准备工作区，同时导出配置和一个批次：

```powershell
python scripts/export_gpm_offline_package.py 67526 --branch main --export-config --output temp/offline
```

日常只追加批次，不改共享配置：

```powershell
python scripts/export_gpm_offline_package.py 67527 --branch main --output temp/offline
```

配置变更时单独更新：

```powershell
python scripts/export_gpm_offline_package.py --export-config --output temp/offline
```

`--output` 是工作区根目录，脚本自动写入其 `config/` 和 `data/`，不再接受旧版的输出文件路径或以 `data` 为根的用法。脚本使用临时文件加原子替换，避免查看器读到尚未写完的 ZIP。若新批次涉及新地图，先更新共享配置再放入批次包。

线上下载分别使用现有接口：

```text
GET /api/gpm-heatmaps/configuration/export?scope=all
    → config/heatmap.zip

GET /api/gpm-heatmaps/uploads/{batch_id}/offline-package?branch_tag=main
    → data/SceneScope-heatmap-<branch>-<batch>.ssheat
```

构建 Windows 便携查看器：

```powershell
scripts/build_gpm_offline_viewer.ps1 -OutputDir temp/offline/runtime
```

输出目录为 `temp/offline/runtime/SceneScopeOffline/`，只需分发 EXE 及 `config/`、`data/` 目录。`-OutputDir` 也支持绝对路径。可把导出脚本的 `--output` 直接指向此目录准备分发数据；构建本身不读取业务库或导出配置。

使用 PyInstaller `--onefile`，DLL 和前端一起内嵌 EXE，避免分发独立 DLL 时被 P4 忽略规则跳过。启动时运行依赖和前端会自动解压到系统临时目录，因此启动比目录版多一次解压；配置和批次仍从 EXE 同级目录读取，不需要安装 Python。

从旧目录版升级只需替换 EXE。旧 `_internal/` 和 `site/` 不再使用，也不需要纳入新版本分发；构建脚本不会自动删除它们或变更其 P4 状态。需要调试前端时可用 `--site <dist目录>` 显式覆盖内嵌版本。

源码方式启动：

```powershell
python scripts/gpm_offline_viewer.py --data temp/offline/data --site frontend/dist
```

默认读取 `data` 同级的 `config/heatmap.zip`，也可用 `--config <配置ZIP路径>` 指定位置。查看器仅监听 `127.0.0.1`。离线前端只显示热力图导航、刷新按钮和“离线数据”状态；未知 API 返回 JSON 404，业务 POST 返回 405，日志 POST 返回 204，其他未实现方法由标准库返回 501。

## 验证与历史数据

针对共享配置拆分的自动化测试覆盖：批次不携带配置或底图、配置与批次分别导出、运行中增加批次、共享底图读取、跨包变化与趋势、统一更新历史批次配置、在线/离线标尺一致，以及缺失配置、不完整配置和旧格式拒绝。

旧版自包含方案曾记录批次 67526 有 1 张地图、105 个点位，包约 3.5 MiB，Windows 查看器约 19.6 MiB，分发 ZIP 约 10.7 MiB，导出约 2.1 秒。这些是拆分前的实测，不能作为 v2 包体积或性能结果；新结构的实际收益随底图大小、配置规模和批次数量变化。

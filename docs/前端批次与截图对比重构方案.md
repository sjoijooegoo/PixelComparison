# 前端批次与截图对比重构方案

> 状态：产品方案已确认，可进入实现
> 确认日期：2026-08-19
> 适用项目：PixelComparison

## 1. 背景

当前“批次管理”同时承载批次表格和多批次截图网格，并通过“列表 / 列表图”切换；“对比结果”又单独承载历史记录、状态汇总、检查点列表、图片详情和指标。这导致批次查询、截图浏览、对比选择、历史浏览和结果详情共用大量全局状态，页面职责不清晰，路由与状态之间也容易互相覆盖。

本次重构把产品能力收敛为两个明确工作区：

- **批次管理**：批次记录的查询和维护目录，只展示表格。
- **截图对比**：同一分支、同一场景内的截图网格，负责基线选择、对比批次选择、对比执行和差异热力图查看。

旧“对比结果”页面和“对比历史”前端入口彻底删除。后端对比记录、检查点指标、热力图文件、任务及查询接口继续保留，并维持现有 14 天淘汰策略。

## 2. 已确认的产品决策

1. 顶部“对比结果”改名为“截图对比”。
2. 批次管理不再区分列表和列表图，只展示所有符合筛选条件的批次表格。
3. 截图对比页面复用当前列表图的视觉和交互，以最右侧差异热力图列呈现结果。
4. 不再提供对比汇总、通过/警告/失败统计、检查点状态列表、像素指标或对比历史浏览界面。
5. 历史结果只有在用户重新选择相同的基线和对比批次时才会自动恢复热力图。
6. 批次表格移除“设为基线”、“设为对比”和“截图对比”行操作，统一从顶栏进入截图对比。
7. `/batches/:sceneId` 重定向到 `/screenshot/:sceneId`；`/batches` 继续作为批次管理入口。
8. `/comparison` 和 `/comparison/:id` 路由及页面完全删除，不提供兼容详情页；旧地址进入全局兜底 `/batches`。
9. 批次管理与截图对比使用相互隔离的筛选、请求、加载和错误状态。
10. 截图对比的基线和对比批次写入 URL，F5 和复制链接后可以恢复。
11. 对比历史数据继续执行当前固定 14 天保留规则，不改为永久保存。

## 3. 目标与非目标

### 3.1 目标

- 让批次管理与截图对比各自只有一个清晰职责。
- 消除 `batchView` 以及两个页面共用同一筛选对象的状态耦合。
- 让截图对比的分支、场景和两个批次由 URL 驱动，刷新和分享行为可预测。
- 保留当前网格的折叠、滚动、大图预览、邻图预加载、缩略图和热力图能力。
- 对比任务在切场景、切分支或离开页面后不得回写旧状态。
- 保留现有后端数据模型、算法、热力图文件和历史数据保留策略。

### 3.2 非目标

- 不重新设计截图网格的视觉样式。
- 不修改像素对比算法、阈值或热力图生成逻辑。
- 不恢复任何形式的对比历史、结果汇总或指标详情 UI。
- 不修改烘培数据的存储、统计或趋势含义。
- 不改变批次、分支和数据能力的领域规则。
- 不增加“全部分支”选项；页面始终处于一个明确分支中，默认 `main`。
- 不改变对比记录的 14 天淘汰规则。

## 4. 目标信息架构

顶部栏目按以下顺序展示：

| 栏目 | 路由 | 页面职责 |
|---|---|---|
| 批次管理 | `/batches` | 批次表格、筛选、预览、跳转、删除 |
| 截图对比 | `/screenshot/:sceneId?` | 截图网格、基线/对比选择、差异热力图 |
| 烘培数据 | `/map-build/:sceneId?` | 保持现有烘培网格和趋势能力 |
| 项目设置 | `/settings` | 保持现有项目配置能力 |

页面间只传递明确的上下文：

```text
顶栏 --分支/场景--> 截图对比
烘培数据 --分支/场景---------> 截图对比
截图对比 --分支/场景---------> 烘培数据
```

日期、画质、分页、滚动位置等页面私有状态不得跨工作区互相覆盖。

## 5. 路由规范

### 5.1 路由表

| 路由 | 行为 |
|---|---|
| `/` | 重定向到 `/batches` |
| `/batches` | 打开批次管理表格；查询参数恢复筛选和页码 |
| `/batches/:sceneId` | 重定向到 `/screenshot/:sceneId`，保留查询参数 |
| `/screenshot` | 打开截图对比空态，等待用户选择场景 |
| `/screenshot/:sceneId` | 打开指定场景的截图对比网格 |
| `/map-build/:sceneId?` | 保持现状 |
| `/settings` | 保持现状 |
| `/comparison` | 不注册；由全局兜底重定向到 `/batches` |
| `/comparison/:id` | 不注册；由全局兜底重定向到 `/batches` |
| 其他未知路由 | 重定向到 `/batches` |

### 5.2 截图对比 URL

标准 URL：

```text
/screenshot/Coral_WP?branch_tag=main&quality=4&date_mode=range&from=2026-08-06&to=2026-08-19&baseline=1238&current=1241
```

参数含义：

| 参数 | 必填 | 含义 |
|---|---:|---|
| `sceneId` | 否 | 路径中的场景 ID；缺省时展示选场景空态 |
| `branch_tag` | 否 | 当前分支；缺省或非法时规范化为 `main` |
| `quality` | 否 | 画质档位 0～5；`all` 表示全部画质，缺省时使用项目默认画质 |
| `date_mode` | 否 | `range` 为连续范围，`days` 为指定日期 |
| `from` / `to` | 否 | `range` 模式的起止日期，连续范围最多 14 天 |
| `dates` | 否 | `days` 模式的逗号分隔日期列表 |
| `baseline` | 否 | 基线批次 ID |
| `current` | 否 | 对比批次 ID |

约束：

- `baseline` 与 `current` 不能相同。
- 两个批次必须属于 URL 指定的分支和场景，并且都具有截图能力。
- 非法、已删除、无截图或跨分支/跨场景参数必须被忽略，并通过 `router.replace` 从 URL 中清除。
- 分支或场景切换必须继承当前画质和日期；画质或日期变化使用 `router.replace` 更新 URL，并清除当前角色，避免角色批次反向覆盖用户刚修改的筛选。
- 旧链接缺少筛选参数时使用项目默认筛选并规范化 URL；非法画质、日期和超长范围回退默认。
- URL 中的画质和日期筛选始终优先；只恢复当前筛选结果内可见的角色，冲突角色从 URL 中清除，刷新不得自动切换为“指定日期”。
- 选择、替换或取消角色后使用 `router.replace` 更新当前 URL，不为每次按钮点击制造浏览器历史节点。
- 浏览器后退/前进必须按 URL 恢复角色，不能由隐藏的全局记忆反向覆盖 URL。

### 5.3 顶部导航传递规则

- 直接点击“截图对比”进入 `/screenshot?branch_tag=<当前路由分支>`，不擅自选择第一个场景。
- 从顶栏进入截图对比时只携带当前分支，场景和角色在工作区内选择。
- 在截图对比与烘培数据之间切换时携带当前 `branch_tag` 和 `sceneId`。
- 进入项目设置不携带数据页面参数。
- 顶栏不得通过某个全局筛选对象推断当前分支；优先读取当前路由，缺省才使用 `main`。

## 6. 批次管理页面

### 6.1 页面内容

批次管理只包含：

1. 批次筛选栏。
2. 批次数量标题。
3. 批次表格。
4. 分页。

必须删除：

- “列表 / 列表图”切换。
- 列表视图上方的基线/对比选择条。
- 表格中的“设为基线”和“设为对比”。
- `BatchTable` 对截图网格的导入和条件渲染。

### 6.2 筛选规则

保留当前批次筛选条件：

- 分支。
- 场景 ID。
- 画质。
- 创建时间：范围或指定日期。
- 清空。

“所有批次”指当前分支和当前筛选条件下的全部数据能力，不只包含带截图的批次，也包括仅烘培批次和待补传批次。仍按后端分页返回，不一次加载全库。

批次管理的筛选、页码、加载和错误状态只能由批次管理模块持有。分支、场景、日期和页码同步到 URL；F5 按 URL 恢复。批次管理不提供画质筛选，旧 URL 中的 `quality` 参数会被忽略并清理。无参数 `/batches` 默认使用 `main`、全部场景和项目默认日期范围；动态页大小不写入 URL。

### 6.3 表格操作

| 操作 | 有截图 | 有烘培数据 | 行为 |
|---|---:|---:|---|
| 预览 | 必须 | 无要求 | 打开单批次截图画廊；无截图时置灰 |
| 查看烘培数据 | 无要求 | 必须 | 跳转到对应场景和批次的烘培页面；无烘培数据时置灰 |
| 删除 | 无要求 | 无要求 | 保持现有二次确认和级联删除语义 |

批次表格不再放置“截图对比”行操作；用户通过顶栏进入截图对比工作区。

## 7. 截图对比页面

### 7.1 页面结构

页面自上而下为：

1. 独立截图筛选栏。
2. 截图网格标题和数量。
3. 当前多批次二维截图网格。
4. 吸附在最右侧的差异热力图列。

不增加历史抽屉、结果详情层或下方指标区域。

### 7.2 筛选栏

保留当前列表图使用的条件：

- 分支。
- 场景 ID。
- 画质。
- 创建时间：范围或指定日期。
- 清空。

规则：

- 分支默认 `main`，不支持“全部分支”。
- 场景 ID 是工作区必要条件；没有场景时不请求网格。
- 场景选项顺序继续遵循场景目录；当前分支、画质和创建时间筛选内没有完整截图的场景显示灰色，但仍允许选择，当前已选场景不会被自动切换。
- 日期范围继续执行最多 14 天限制；较远日期使用“指定日期”。
- “清空”只恢复项目默认画质和日期，保留当前分支和场景。
- 重置后仍在网格内的角色继续保留；被筛选隐藏的角色从状态和 URL 中清除。
- 截图筛选与批次管理筛选完全隔离。

### 7.3 从 URL 恢复角色

当 URL 带 `baseline` 或 `current` 时，页面先校验批次存在、具有截图、分支和场景匹配，再按 URL 中的画质和日期只加载一次网格。仅恢复网格内可见的角色；筛选外角色从 URL 中清除，不得为了显示角色反向修改筛选。

为避免用模糊的 `q` 查询拼装路由状态，新增精确只读接口：

```http
GET /api/batches/{batch_id}
```

响应复用现有 `batch_dto`，包含 `branch_tag`、`scene_id`、画质、创建时间和两种数据能力。批次 ID 全局唯一，因此无需新增数据库字段。

### 7.4 网格行为

保持现有行为：

- 批次从左到右按旧到新排列。
- 检查点从上到下排列。
- 首列检查点名称、批次列折叠、固定热力图列保持现状。
- 切场景后纵向滚动归零；横向定位规则保持当前实现。
- 自动刷新不打断用户主动滚动。
- 缩略图懒加载；点击后加载原图。
- 大图支持方向键切换、共享缩放和平移、相邻原图预加载。
- 页面失活时关闭大图并停止当前探针和预加载队列。

空态：

| 条件 | 提示 |
|---|---|
| 未选择场景 | 请选择一个包含截图数据的场景 |
| 当前分支和场景无截图 | 当前分支和场景下没有包含截图的批次 |
| 筛选后无截图 | 当前筛选条件下没有包含截图的批次 |
| 网格请求失败 | 显示错误原因和“重新加载” |

### 7.5 基线与对比选择

- 批次列表行入口指定的批次默认作为 `current`。
- 网格未选择基线时，点击其他批次列按钮设为基线。
- 已有基线时，点击未选批次设为或替换 `current`。
- 点击已选角色取消对应选择。
- 两个角色不得引用同一批次。
- 切场景或切分支立即清空两个角色、热力图和 URL 参数。
- 角色只由当前 URL 和当前网格数据共同确定；删除 `rolesByScene` 这类隐藏权威状态。

## 8. 差异热力图与对比任务

### 8.1 热力图列表头状态

| 状态 | 表头表现 | 允许操作 |
|---|---|---|
| 未选满两个角色 | 显示“选择基线 / 对比批次” | 无 |
| 查询已有结果中 | 显示加载状态 | 可取消角色 |
| 没有历史结果 | 显示“发起对比” | 发起对比 |
| 后端正在计算 | 显示 `对比中 done/total` | 允许离开页面，不重复起任务 |
| 已有结果 | 显示“差异热力图”和低调的“重新对比” | 查看大图或强制重算 |
| 查询或计算失败 | 显示错误和“重试” | 重试当前动作 |

不再把“差异热力图”标题做成跳转到旧结果页的链接。

### 8.2 历史结果复用

当两个角色都已选择时调用：

```http
GET /api/comparisons/lookup?batch_id=<current>&ref_batch_id=<baseline>
```

- 已完成：直接展示返回的检查点热力图映射。
- 不存在：展示“发起对比”。
- 正在计算：恢复任务进度轮询。
- 用户点击单个热力图时，仅打开该热力图大图，不加载旧指标详情。

前端不再主动调用以下历史/详情接口，但后端继续保留：

- `GET /api/comparisons`
- `GET /api/comparisons/{comparison_id}/scenes`
- `GET /api/items/{item_id}`

### 8.3 发起和重新对比

发起对比继续使用：

```http
POST /api/comparisons
```

请求方向固定为：

```json
{
  "batch_id": "<current>",
  "ref_batch_id": "<baseline>",
  "force": false
}
```

“重新对比”使用相同批次并发送 `force: true`。完成后重新执行 lookup，更新带缓存版本的热力图 URL；不得进入任何结果页面。

### 8.4 后端兼容性修正

当前实现会先创建空的 `Comparison` 行再启动后台任务。相同批次对仍在 `_RUNNING` 时，再次调用创建接口可能在检查运行任务之前把空记录误报为 `done`；lookup 也无法区分“已完成”与“行已创建但检查点尚未生成”。新页面会把这种响应误显示成空白热力图，因此必须同步修正：

1. `create_comparison` 在返回已有结果前先检查该对比是否处于 `_RUNNING`，运行中复用原 `task_id`。
2. `comparison/lookup` 向后兼容地增加 `status`、`ready`、`task_id`、`done` 和 `total` 字段。
3. 完成记录返回 `status=done, ready=true`。
4. 正在运行返回 `status=running, ready=false` 和任务信息。
5. 不存在返回 `status=missing, exists=false, ready=false`。
6. 服务异常退出留下的无检查点空行不得视为已完成；下一次发起时应复用该行重新计算。

不删除或重命名现有响应字段，保证旧上报脚本和现有调用方继续工作。

### 8.5 请求竞态与离开页面

截图对比模块为以下资源分别维护单调请求序号和取消控制器：

- 批次元数据解析。
- 截图网格。
- 对比 lookup。
- 对比任务轮询。

每个请求捕获完整上下文键：

```text
branch_tag + scene_id + final filters + baseline + current
```

只有上下文键和请求序号仍为最新时才能写回状态。切分支、切场景、修改筛选、修改角色、清空或离开页面必须立即使旧请求失效。

离开页面只停止前端轮询，不取消后端线程。重新进入并选中同一批次对时通过 lookup 恢复运行状态或最终热力图。

## 9. 状态模块设计

不得通过给当前单体 Pinia store 增加更多字段来伪装隔离。目标是把变化频率和生命周期不同的状态放到三个有明确接口的模块中。

### 9.1 Project 模块

负责：

- 项目设置。
- 全局场景目录和数据能力元信息。
- 手动上报弹窗状态。
- 应用初始化错误状态。

它不拥有当前页面分支、场景、日期或画质。

### 9.2 Batch Catalog 模块

负责：

- 批次管理筛选。
- 批次列表、总数和分页。
- 列表请求序号、加载和错误状态。
- 批次删除后的列表刷新。

对外接口应收敛为初始化、应用筛选、重置、刷新、翻页和删除，不暴露截图网格状态。

### 9.3 Screenshot Comparison 模块

负责：

- 截图筛选。
- 网格、缓存和折叠列。
- URL 角色解析和批次元数据补全。
- 基线/对比角色。
- 热力图 lookup。
- 对比任务发起、轮询和重算。
- 相关请求取消及竞态保护。

它不加载对比历史、场景状态列表或指标详情。

### 9.4 初始化流程

应用启动只初始化 Project 模块并挂载外壳。路由页面各自加载所需数据：

```text
router ready
   │
   ├── Project.init(): meta + settings
   │
   └── mount app
         ├── /batches   -> BatchCatalog.init(route)
         ├── /screenshot -> ScreenshotComparison.init(route)
         └── /map-build -> MapBuildView.init(route)
```

深链 `/screenshot/:sceneId` 首屏不得先发送无场景的批次或网格请求，也不得为了截图页面加载全局批次表格。

## 10. 模块与文件调整

### 10.1 新增或重命名

建议目标文件：

- `frontend/src/views/ScreenshotComparisonView.vue`
- `frontend/src/components/ScreenshotComparisonGrid.vue`（由 `BatchGrid.vue` 重命名并收敛职责）
- `frontend/src/components/BatchCatalogFilters.vue`
- `frontend/src/components/ScreenshotFilters.vue`
- `frontend/src/stores/projectStore.js`
- `frontend/src/stores/batchCatalogStore.js`
- `frontend/src/stores/screenshotComparisonStore.js`

## 11. 刷新、上报与 keep-alive

### 11.1 自动刷新

顶栏每分钟只刷新当前活动页面：

- `/batches`：刷新元信息和批次列表。
- `/screenshot`：刷新元信息和当前网格，再校验 URL 角色。
- `/map-build`：执行现有页面刷新。
- `/settings`：不自动刷新数据工作区。

自动刷新不得重置筛选、角色、URL、大图缩放、网格折叠或用户主动滚动位置。新增批次仅追加到正确位置。

### 11.2 上报完成

手动上报完成后：

1. 刷新 Project 元信息，使新分支、场景和数据能力可见。
2. 只调用当前活动页注册的刷新动作。
3. 不同时刷新隐藏的批次表和截图网格。
4. 外部脚本上报仍依赖当前一分钟自动刷新或用户手动刷新。

### 11.3 keep-alive

只缓存 `ScreenshotComparisonView`，用于保留重型网格 DOM 和滚动体验。被缓存页面必须：

- 只在当前路由以 `/screenshot` 开头时响应路由 watcher。
- `onDeactivated` 关闭大图、取消图片预加载、lookup 和轮询。
- `onActivated` 重新按当前 URL 校验状态，并对选中批次执行 lookup。
- 不得在失活后修改全局分支或替换其他页面 URL。

批次管理无需 keep-alive；筛选和分页由 URL 恢复，store 只持有当前路由对应的运行时状态。
